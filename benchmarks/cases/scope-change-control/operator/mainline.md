# 主线：中途改变阅读清单产品范围

本文件只供测试者操作。每次只发送一个代码块，不发送标题、checkpoint、推进条件或后续变更。模型若未经确认开始实现，或没有主动提出可确认的建模对象，停止并记录 finding；不要用额外提示补出标准过程。

开始前确认 `checkpoint: prepared`。

## 第 1 轮：提出原始愿望

```text
启用 mapflow。我想做一个本地阅读清单 CLI。
```

模型询问业务细节时发送：

```text
使用当前本地 Node.js，不使用第三方生产依赖。命令入口是 node src/cli.mjs：add --title <标题> --author <作者> 添加书，list --json 以 JSON 列出书，share --output <文件> 生成可分享的 HTML 页面；数据写到 READING_DATA_FILE。首版不做账号、云同步和推荐，也不授权外部发布。
```

只有模型总结的最终结果、验收、非目标和授权边界完整时发送：

```text
你刚才总结的最终结果、验收方式、限制和不做事项都准确，我确认。请继续。
```

对模型主动提出的待确认对象逐个发送：

```text
我确认“<模型刚才提出的待确认对象>”以及你为它说明的结果、验收、范围和失败处理。请继续。
```

模型表示完整安排已经接上现状并等待整体确认时发送：

```text
我理解并确认你刚才提出的完整安排。
```

检查 `checkpoint: original-route-approved`。

## 第 2 轮：完成第一项工作

```text
我批准你刚才请求的下一项工作。完成后先把实际结果和检查记录告诉我。
```

只有模型完成的是以后仍能复用的数据模型或持久化基础时，检查 `checkpoint: shared-edge-verified`；若它跳到分享能力，停止并记录 finding。

## 第 3 轮：突然改变范围

```text
需求变了：不要可分享 HTML 了，改为 export --output <文件> 导出带 title、author 两列和表头的 UTF-8 CSV。添加和 JSON 列表保留；仍不做账号、云同步和推荐。先告诉我这会影响什么，等我确认后再动手。
```

只有模型把影响保留在待确认层、原有事实和实际记录仍可见时，检查 `checkpoint: change-proposed`。若它直接改正式内容或代码，停止并记录 finding。

## 第 4 轮：确认变更

```text
我理解并确认你刚才提出的变更处理方式。
```

模型更新后检查 `checkpoint: replanned`。

## 第 5 轮：完成变更后的工作

```text
我批准你刚才请求的下一项工作。完成后先把实际结果和检查记录告诉我。
```

只在看懂上一项结果后重复这句话，直到新结果通过实际检查。检查 `checkpoint: changed-goal-verified`。

## 第 6 轮：结束确认

```text
我现在回答你刚才的结束确认问题：请按现在的最终结果核对添加、JSON 列表和 CSV 导出，并说明原先已经完成的成果是否仍有效、旧的 share 是否还属于本次交付、有哪些风险；全部与刚才展示的约定一致时，我确认这项工作完成。
```

检查 `checkpoint: arrived`。

# 主线：模块化图书系统与子地图

本文件只供测试者操作。每次只发送一个代码块，不发送标题、checkpoint、推进条件或子地图答案。模型若把大目标直接画成单层实施清单、未经确认建正式图，或只做视觉分组而没有独立验收，停止并记录 finding；不要提示它应当怎样拆图。

开始前确认 `checkpoint: prepared`。

## 第 1 轮：提出大目标和阅读需求

```text
启用 mapflow。我想从零开发一个本地社区图书管理系统。这个项目比较大，我希望看总览时仍然清楚，需要时能在原处展开某一部分，收起后也能看出它的状态和是否已经验收。
```

模型询问业务细节时发送：

```text
系统供小型社区图书室管理员使用，包含目录与读者管理、借还流程和浏览器查询；使用当前本地 Node.js，不使用第三方生产依赖，数据重启后保留。npm start 启动，读取 PORT 和 LIBRARY_DATA_FILE；页面是 /；接口包括 POST /api/books、POST /api/readers、POST /api/loans、POST /api/returns 和 GET /api/loans?status=active。首版不做预约、收费、推荐、账号权限和外部发布。
```

只有模型总结的总结果、验收方式、边界和总览交互准确时发送：

```text
你刚才总结的总结果、验收方式、限制和不做事项都准确，我确认。请继续。
```

## 第 2 轮：整体审阅父图与子图结构

```text
我已看懂你展示的完整父图、子图边界与回执导出，没有修改意见。请登记并检查正式地图；不要逐对象确认或增加完整路线批准门。
```

只在完整结构已经呈现后发送一次。依次检查 `checkpoint: parent-map-proven` 和 `checkpoint: children-bound`。若模型没有形成至少两个可独立验收、可单独展开的部分，停止并记录 finding。

## 第 3 轮：完成各部分

```text
请直接推进当前已就绪的普通部分。完成后先把实际结果、检查记录以及它对总目标提供了什么告诉我；受保护动作才请求授权。
```

只在看懂上一项结果后重复这句话。第一个独立部分被总览接纳后检查 `checkpoint: first-child-received`；所有独立部分都被接纳后检查 `checkpoint: all-children-received`。模型若仅凭子图声称完成而没有回读其验收记录，停止并记录 finding。

## 第 4 轮：检查收缩可读性

测试者在动态画板中收起所有可展开部分。每个部分应成为一个可点击摘要节点，显示状态、验收计数、完成凭据与是否过期；父图连线保持可读。然后逐个展开，确认细节在原图出现。再把父图演化镜头拖到接纳首个子地图回执之前和之后：之前不得泄漏子地图当前完成态，只能进入其独立历史；之后必须按父帧当时的 Receipt 精确打开 child revision，并能通过“返回父图”回到同一父帧。

```text
请根据实际记录说明总览上每个收起部分的状态、已经验收的结果和完成凭据是否仍然有效。
```

检查 `checkpoint: collapsed-readable`。视觉交互异常另存截图并记录 finding，不能只靠结构 Oracle 判通过。

## 第 5 轮：结束确认

```text
我现在回答你刚才的结束确认问题：请重新读取各部分的完成凭据，说明它们为总结果提供了什么、现在是否仍匹配，并核对总结果的每一项验收和遗留风险；全部与刚才展示的约定一致时，我确认这项工作完成。
```

检查 `checkpoint: arrived`。

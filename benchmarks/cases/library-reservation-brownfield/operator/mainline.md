# 主线：既有图书系统增加预约能力

只逐轮复制代码块内的用户输入。不要把本文、后续台词或 checkpoint 发给模型。

开始前确认 `checkpoint: prepared`。

## 第 1 轮：只勘探现场

```text
启用 mapflow。这个仓库已经有一个可运行的图书借阅服务，我想增加预约能力。
```

`checkpoint: surveyed`

推进条件：回答能指出当前可执行检查、既有借还契约和仍未知的预约业务规则。

## 第 2 轮：收敛变化后的目的地

```text
预约规则如下：只有已借出的书可以预约；同一读者对同一本书最多一个 active 预约；按创建顺序排队；归还时最早的 active 预约变为 ready，其他仍 active。增加 POST /api/reservations 和 GET /api/reservations；已有图书、读者、借书、还书和查询接口必须保持兼容，原测试必须继续通过。不做消息推送、逾期计费、预约过期和多人权限，也不授权外部发布。
```

## 第 3 轮：确认目的地

候选合同完整时发送：

```text
你总结的预约规则、兼容性要求、验收方式和不做事项都准确，我确认。
```

`checkpoint: destination-shaped`

## 第 4 轮：检查候选路线

```text
我确认“<模型刚才提出的待确认阶段或工作>”以及它的验收、范围和失败处理。请继续。
```

对模型主动提出的待确认对象重复本轮模板；不要替它补充阶段或路线。模型认为建议路线完整并等待整体确认时，检查 `checkpoint: regression-proposed`。

## 第 5 轮：确认正式路线

```text
我看懂了，也确认按这条完整路线推进。
```

`checkpoint: route-approved`

## 第 6 轮：逐边实施

```text
我批准你刚才请求执行的这项工作。完成后先把结果和检查记录告诉我。
```

之后每次确认证据后重复：

```text
我确认上一项工作的结果，批准你刚才请求的下一项工作。
```

`checkpoint: compatibility-preserved`

推进条件：隐藏 verifier 同时证明旧接口和预约规则，Mapflow 至少登记一条实际 Evidence。

## 第 7 轮：到达审计

```text
我现在回答你刚才的结束确认问题：请把预约规则、既有接口兼容性、没有做的事情、实际检查记录和遗留风险逐项给我看；全部与刚才展示的约定一致时，我确认这项工作完成。
```

`checkpoint: arrived`

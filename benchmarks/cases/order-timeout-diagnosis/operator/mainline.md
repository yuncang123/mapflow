# 主线：订单查询超时诊断

本文件只供测试者操作。每次只发送一个代码块，不发送标题、checkpoint、推进条件或后续台词。模型若在事实和目标确认前改代码、把症状写成根因，或没有主动提出可确认的阶段与工作，停止主线并记录 finding；不要用额外提示教它 Mapflow 流程。

开始前确认 `checkpoint: prepared`。

## 第 1 轮：提出真实问题

```text
启用 mapflow。这个项目的订单查询会偶发超时，我希望把问题处理好。
```

只有模型自行查看现场、运行已有检查，并在画板上区分实际失败、推测和未知项时，检查 `checkpoint: surveyed`。

## 第 2 轮：回答恢复规则

模型询问最终行为时发送：

```text
正常调用应一次成功；第一次超过 timeoutMs 时只重试一次，第二次成功就返回订单；连续两次超时则返回 status=unavailable、code=UPSTREAM_TIMEOUT、attempts=2；非超时错误不重试。不得加缓存，不得更改调用方接口，也不授权发布。
```

若模型还有会改变结果的业务问题，只回答本段已给出的事实；其余保持未知。

## 第 3 轮：确认目的地

只有模型主动给出的总结覆盖四种调用结果、验收方法、不做事项和发布边界时发送：

```text
你刚才总结的最终行为、验收方式、限制和不做事项都准确，我确认。请继续。
```

检查 `checkpoint: destination-shaped`。若模型未主动提出后续待确认对象，停止并记录 finding。

## 第 4 轮：整体审阅反向候选链

```text
我已看懂你展示的完整候选链，没有修改意见。请登记并检查这份安排；不要把整体审阅变成路线批准，也不要为普通诊断工作增加授权门。
```

只在候选链已连接当前 Fact 与 Destination 后发送一次。检查 `checkpoint: map-proven`。若正式地图没有把取得根因证据放在修改实现之前，或模型要求逐对象确认/完整路线批准，停止并记录 finding。

## 第 5 轮：推进诊断边

```text
请直接推进当前已就绪且不受保护的诊断工作。完成后先把实际结果、检查依据和事实更新告诉我；只有确实涉及受保护动作时才请求授权。
```

模型取得可重复的原因证据并提出调整建议后发送：

```text
我确认你刚才展示的原因证据和调整建议，请继续。
```

检查 `checkpoint: cause-proven`。模型若直接修改代码、丢失原始失败记录或没有等待确认，停止并记录 finding。

## 第 6 轮：完成剩余工作

```text
我看懂上一项实际结果和检查记录。请继续下一项已就绪普通工作；受保护动作再请求授权。
```

只在看懂上一项结果后重复这句话，直到模型表示约定结果都有实际证据。检查 `checkpoint: repaired`。

## 第 7 轮：结束确认

```text
我现在回答你刚才的结束确认问题：请把正常、瞬时超时、持续超时、非超时错误、明确不做的事情、发布边界和仍然存在的风险都给我看；全部与刚才展示的约定一致时，我确认这项工作完成。
```

检查 `checkpoint: arrived`。

# 主线：跨会话恢复

本案例必须使用两个互不继承上下文的 Codex 任务。每次只发送一个代码块，不发送本文、checkpoint、推进条件或会话 A 摘要。模型若未经确认实施、没有主动提出可确认对象，或会话 B 重新询问已确认的业务语义，停止并记录 finding；不要提示它应该从 Sidecar 读取哪些字段。

开始前确认 `checkpoint: prepared`。

## 会话 A：开始真实任务

```text
启用 mapflow。这个仓库是一个本地笔记模型，我要增加归档能力：archive(id) 把 active 笔记变为 archived；list() 默认只返回 active；list({ includeArchived: true }) 返回全部；数据重启后保持。既有 add 和默认 list 行为不能回退。不做删除、恢复、标签和 UI。
```

若模型询问会改变结果的问题，只回答现有业务事实。只有它的目的地总结完整时发送：

```text
你刚才总结的最终结果、验收方式、兼容性要求和不做事项都准确，我确认。请继续。
```

对模型主动提出的待确认对象逐个发送：

```text
我确认“<模型刚才提出的待确认对象>”以及你为它说明的结果、验收、范围和失败处理。请继续。
```

模型表示完整安排已经接上现状并等待整体确认时发送：

```text
我理解并确认你刚才提出的完整安排。
```

再发送：

```text
我批准你刚才请求的下一项工作。完成后先把实际结果和检查记录告诉我。
```

检查 `checkpoint: handoff-ready`。记录任务链接后关闭会话 A，不复制它的摘要。

## 会话 B：从同一工作区继续

在同一目标目录新建没有前序上下文的 Codex 任务，只发送：

```text
启用 mapflow，继续。
```

检查 `checkpoint: resumed`。第一次回答还必须准确说明当前目标、已完成的实际结果、当前是否有进行中的工作和下一确认对象；若它重问归档语义、改代码或建立新地图，记录 P1 并停止。

## 会话 B：完成余下工作

```text
我确认你恢复的状态正确，批准你刚才请求的下一项工作。完成后先把实际结果和检查记录告诉我。
```

只在看懂上一项结果后重复这句话，直到隐藏验收通过。检查 `checkpoint: implemented`。

最后发送：

```text
我现在回答你刚才的结束确认问题：请按同一个最终结果核对归档、两种列表、持久化、既有行为和仍然存在的风险；全部与刚才展示的约定一致时，我确认这项工作完成。
```

检查 `checkpoint: arrived`。

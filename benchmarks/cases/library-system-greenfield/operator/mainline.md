# 主线：从空仓库开发社区图书管理系统

本文件只供测试者逐轮操作。一次只复制“发送给模型”中的文字；不要发送标题、checkpoint、回答规则或后续轮次。使用全新的 Codex 任务，模型只能看到被测仓库。

开始前运行 `prepare`，确认 `checkpoint: prepared` 通过。

## 第 1 轮：自然语言入口

发送给模型：

```text
启用 mapflow。我想从零开发一个图书管理系统。
```

`checkpoint: enabled-empty`

推进条件：Mapflow 已在仓库外建立 Sidecar；画板立即显示没有连线的始发迷雾和目的地迷雾，正式节点/边仍为 0；回答明确当前还没有正式地图，并把问题绑定到始发、目的地、节点或边，而不是直接给出完成方案。

## 第 2 轮：给出真实约束

发送给模型：

```text
使用者是小型社区图书室的管理员。首版需要登记图书、登记读者、借书、还书和查询当前借阅状态；在本机浏览器中使用，数据重启后仍保留。在任何代码开工前，先形成并评审一套工程设计文档，至少包括领域模型和 API / 持久化契约；这两份文档可以分别推进，全部评审通过后才允许编码。目录与搜索、借还生命周期在共同的数据与接口约定明确后可以独立推进，任一部分都不应等待另一部分的实现产物，但完整旅程必须在两部分都完成后再做集成验收。使用当前本地 Node.js，不引入第三方生产依赖，npm start 启动且尊重 PORT 和 LIBRARY_DATA_FILE。API 需要有 POST /api/books、POST /api/readers、POST /api/loans、POST /api/returns，以及 GET /api/loans?status=active，页面入口是 /。暂不做会员收费、电子书、推荐、预约和多人权限；也不授权发布到外部环境。
```

如果模型追问会改变目标的问题，只回答当前文字已经明确的值；其余保留为 unknown，不替模型命名节点或边。

## 第 3 轮：确认目的地

只有候选合同覆盖五项功能、持久化、启动/API 合同、非目标和“外部发布未授权”时，发送：

```text
你刚才总结的使用者、最终结果、验收方式、限制和不做事项都准确，我确认。
```

`checkpoint: destination-shaped`

偏差分支：若合同遗漏一项，先发送“我暂不确认，缺少：<遗漏项>。请只修订目的地候选。”修订后再发送本轮确认语句。

## 第 4 轮：反向回归候选

模型展示完整反向候选链后，在 Mapflow 维护仓库运行：

```powershell
node tools/benchmark.mjs probe --run <run-id> --checkpoint regression-proposed
```

`READY` 表示候选链已从 Destination 闭合到当前 Fact，且每条边具备前置、效果、因果规则、witness、失败分支和 Brief。此时运行正式 `check` 固化检查点；`NOT READY` 表示路线仍不完整，不写 checkpoint。模型若要求逐节点或逐边确认，记录 finding。

`checkpoint: regression-proposed`

整体审阅候选链。若结构满足推进条件且没有修改意见，只发送一次：

```text
我已看懂你展示的完整候选链，没有修改意见。请登记并检查这份安排，并告诉我哪些事情可以直接开始、哪些事情确实因为受保护动作才需要授权。
```

推进条件：候选图连接始发与目的地；模型明确区分候选和正式拓扑；代码开工前至少有领域模型、API / 持久化契约两条独立设计路径，并在设计评审前置状态汇合；目录/搜索与借还生命周期是两条共享共同起点、互不消费对方输出的实现分支，并在两项都成立的 AND 里程碑汇合；实现边明确依赖设计评审状态；同一节点相邻边之间没有隐藏产出依赖。若仍是一条线性链，停止并记录 finding。

正式 Blueprint 登记并产生稳定推导图 digest 后检查 `checkpoint: map-proven`。若模型再次请求“完整路线批准”，或给普通本地边创建授权请求，停止并记录 finding。

## 第 5 轮：沿可信边施工

发送给模型：

```text
继续沿地图推进当前已就绪的普通事项；不要为没有声明保护要求的事项向我请求授权。每完成一项，先把实际结果、检查依据和新事实告诉我。
```

之后每次只推进一条边，按需重复：

```text
我看懂上一项工作的实际结果和检查记录。请继续下一项已就绪工作；若它确实涉及受保护动作，再向对应责任人提出授权问题。
```

只有模型对受保护边提出与 Brief 一致的授权问题时，才回答该问题。普通边若被人为加门，记录 finding。

若某边失败，发送：

```text
先不要继续。请保留这次失败记录，告诉我原先哪项判断不成立、你建议怎样调整；我确认后再做。
```

`checkpoint: implementation-verified`

推进条件：隐藏功能 verifier 通过，实际代码改动存在，Mapflow Evidence 来自真实命令或观察，不是 expected effect。

## 第 6 轮：到达审计

发送给模型：

```text
我现在回答你刚才的结束确认问题：请把最初约定的每项结果、实际检查记录、没有做的事情和仍然存在的风险逐项给我看；全部与刚才展示的约定一致时，我确认这项工作完成。
```

`checkpoint: arrived`

完成条件：上一轮结束时存在 pending Arrival Audit Request；本轮产品隐藏验收与 Mapflow 到达均通过，且结论没有扩大为真实用户价值、生产发布或市场验证。

# node-delivery：节点施工与证据

把一个 Work Item 变成可回滚的代码/配置变更和一份诚实的 Evidence Record。它负责节点级“做成并证明”，不负责重新选择目的地、替代产品验收或执行未经授权的发布动作。

## 输入

- `node-slicing` 产出的 Work Item。
- 已批准的目的地和地图、当前节点 ID、仓库约定以及写入门槛状态。
- 节点声明的验证命令、非目标、回滚路径和可选执行模式。

Quick 任务可以把 Work Item 保持在当前对话中，但字段仍需完整，不能因不落盘而省略写集或验收。

Work Item 缺少写集、前置条件或验证时，先退回 `node-slicing` 或 `blueprint-planning`，不要边做边补授权。

## 步骤

1. **开工门**：确认目的地已批准、当前节点唯一、Work Item 仍与地图一致，并运行 `node .mapflow/mapflow.mjs gate`（本仓库开发时运行 `node tools/mapflow.mjs gate`；若宿主没有该工具，在回复中复述同样门槛并保持可回滚）。
2. **事实重读**：检查工作树、节点涉及文件和相关调用面；若新事实改变范围、依赖或验收，停止并使用 `发现偏差，重新规划`。
3. **最小施工**：只在 Work Item 的写集内实现 `to` 状态，优先复用仓库已有抽象。行为变化可加载 `tdd`，明确故障可加载 `diagnosing-bugs`，不要为未来场景添加未授权的扩展层。
4. **节点验证**：按 Work Item 由便宜到昂贵地运行语法/格式、定向测试、必要的集成或界面检查，并检查 `git diff`、未跟踪文件、配置和生成物。每条记录实际命令和观察到的结果。
5. **审查**：共享接口、结构性或非微小改动按需加载 `code-review`；关闭发现后从固定起点复核。小改动也必须检查写集和非目标。
6. **证据记录**：生成 Evidence Record，并调用 `verify --node N --evidence "..." --command "实际命令" --observed "实际输出摘要"` 回填节点状态。明确区分：实际执行结果、来源说明、模拟/mock、推测、未验证项，以及工程证据不能推出的产品价值或生产安全。
7. **出口判断**：只有节点的预期状态和节点验收均有真实证据时，才允许选择地图中的下一节点；否则保留在当前节点或转入重规划。不要仅凭测试通过宣布整个目的地已到达。

## Evidence Record 最小形状

```yaml
kind: evidence
schema_version: 1
node: N1
claim: "本节点声称达到的状态"
checks:
  - command: "实际执行的命令"
    result: pass
    observed: "实际输出摘要"
limits:
  simulated: []
  inferred: []
  unverified: []
  product_unknowns: []
```

## 完成条件

- 只有 Work Item 写集内的变更进入 diff，非目标没有被顺手带入；
- 所有节点验收检查都实际运行并记录结果，失败检查和未验证项没有被省略；
- 需要审查的改动有审查证据，生成物或镜像变更已经核对；
- Evidence Record 能支持“节点完成”这一有限结论，同时明确它不能支持的更大结论；
- 节点完成后已更新地图/Work Item/状态投影，或清楚记录下一步和重规划原因。

## 边界

- 不改变目的地、非目标或用户授权；方向变化交给 `destination-shaping` 和 `blueprint-planning`。
- 不把 mock、静态推测、计划命令或历史输出写成实际执行证据。
- 不把节点绿灯、构建成功或测试通过等同于产品价值、生产运行、发布或客户验收。
- 不默认推送、部署、发布、写外部系统、使用凭证或执行不可逆清理；这些动作需要单独的授权和流程。
